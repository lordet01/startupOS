# StartupOS 작업 화면 개편 · 2026-10-25

- 흰 배경과 딥블루를 대시보드, 기획, Studio, 동기화 창, 로그인에 공통 적용.
- 주 메뉴: 내 앱 / 작업 현황 / 기획 / 빌드·검증 / 배포 / 설치·확인. 운영 메뉴는 별도 그룹으로 유지.
- 내 앱: 검색·보관함·정렬, 진행 단계, 이어서 작업. 이름 변경·복제·보관·이력·휴지통은 더보기에서 실행.
- 새 앱: 이름·아이디어·사용자·문제를 우선 입력. 예산·수익 모델·추가 조건은 접어서 유지.
- 기획: 사용자 흐름·기술 연결·비용 확인 후 빌드로 이동.
- Studio: 범위 확인 / AutoBuild / 미리보기·수정 / 검증 / 배포·설치로 분리. 기존 해시 링크 지원. 탭을 바꿀 때 DOM을 지우지 않아 채팅·첨부 상태를 유지.
- 자동 실행의 한도·유료 API 동의·변경 승인·사용자 검수·배포 전 검증을 유지.
- 작은 화면에서는 내 앱부터 설치까지 다섯 단계 하단 메뉴. 운영 메뉴는 상단 더보기에서 접근.

## Firebase 반영

`firebase/build.cjs`가 동일한 프런트 소스를 인증된 `startupWeb`에 패키징한다. UI 변경은 별도 사본이 아닌 원본 `index.html`, `builder/`, `workspace-ui.js`, `tool-ui.css`에 반영한다.

인증된 Cloud Shell에서 `bash firebase/deploy-ui.sh` 실행. 기존 API·작업 워커·데이터·보안 규칙·권한·비밀값을 다시 배포하지 않는다. 매 배포 전에 의존성 설치·전체 테스트·패키징을 실행한다. 성공 여부는 Firebase CLI의 배포 완료 결과로 확인한다.

`npm run dev`는 로컬 화면 검토 전용이다. 이 환경의 API 쓰기 요청은 503으로 차단되며 유료 AI 호출과 원격 변경을 실행하지 않는다. 운영 배포에는 이 검토 서버가 포함되지 않는다.

## 검증 범위

전체 코드 테스트, Firebase 패키징·인증 회귀, Studio 탭 상태 유지·배포/설치 링크·미구현 단계 안내를 검사한다. 브라우저에서 실제 화면과 입력·탭 이동을 별도로 확인한다. 유료 모델 호출 및 실제 휴대폰 설치 성공은 이 UI 작업의 로컬 테스트에 포함하지 않는다.
