# 군단 편제에서 배운 AutoBuild 에이전트 팀

로마 군단의 계층적 지휘와 작은 단위의 책임 분담을 설계 비유로 사용한다. 역사적 편제는 시대마다 달랐으며 이 구현이 실제 군단의 규모나 효율을 재현한다는 뜻은 아니다. 목표는 단일 책임자가 업무를 나누고, 각 역할의 결과를 검증 가능한 형태로 모으는 것이다.

| 계층 | 책임 | 실행 방식 |
| --- | --- | --- |
| 지휘 | 요구사항, 승인, 한도, 단계 및 산출물 일치 관리 | 기존 브라우저 AutoBuild 상태기계 |
| 계획 | 요청의 제약과 검증 위험 정리 | 서버의 경량 모델 1회 |
| 구현 | 실제 소스 패치 작성 및 정적 검증 | 기존 코드 생성 모델, 최대 3회 |
| 독립 검토 | 요청과 패치의 명백한 결함·위험 검토, 거부 가능 | 서버의 경량 모델 1회 |
| 검증 | 산출물 해시와 서버 검사, 사용자 여정 확인 | 기존 Build 검증과 사용자 승인 |

팀 모드는 AutoBuild 고급 설정에서 선택한다. 기본값은 기존 단일 구현 방식이다. 계획 결과는 참고 자료이며 사용자 지시보다 우선하지 않는다. 검토가 거부되거나 역할 호출이 실패하면 패치를 자동 적용하지 않는다. 기존 소스 편집 허용 범위, 인증, 승인, 빌드 및 수동 검수는 그대로 적용된다. 검토 모델은 실제 테스트를 수행하지 않으며 승인도 정확성을 보증하지 않는다. 외부 작업이 필요하다고 구현자가 보고하면 검토를 생략하고 기존 외부 차단 경로를 따른다.

서버 설정 `OPENAI_TEAM_MODEL`은 계획·검토 모델을 지정한다(기본 `gpt-4.1-mini`); `OPENAI_CODER_MODEL`은 구현 모델을 지정한다. 클라이언트는 모델 이름을 선택할 수 없다. 기존 서버 측 `OPENAI_API_KEY`를 사용하며 키를 브라우저에 보내지 않는다. 모델 접근 권한과 실제 품질은 운영 환경에서 확인해야 한다.

팀 제안은 최대 5회(계획 1, 구현 최대 3, 검토 1)를 선예약하고 성공 시 실제 횟수로 정산한다. 중단·오류는 예약을 보수적으로 유지하고 비용을 미확정으로 표시한다. 한도는 브라우저 실행별 호출 수 제한이며 달러 상한이나 서버 전역·계정별 강제 예산이 아니다. 토큰 비용은 이 경로에서 추정하지 않는다. 탭 종료, 다중 기기 경쟁 및 요청 타임아웃에 대한 기존 AutoBuild 제한도 유지된다. 운영용 전역 예산에는 원자적 서버 원장과 공급자 사용량 대조가 필요하다.

코드 제안과 AI 검토는 순차 실행이며 병렬 분산 워커나 자율적으로 하위 에이전트를 생성하는 시스템은 아니다. 기존 capability 범위와 기존 실행·배포 정책을 넘지 않는다. 모델 호출과 실제 공급자 비용, 실기기 및 운영 배포 검증은 모의 테스트로 증명되지 않는다.
